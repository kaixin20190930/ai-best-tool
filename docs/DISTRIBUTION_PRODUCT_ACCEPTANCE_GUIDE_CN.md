# 产品分发真实验收与用户操作指南

更新日期：2026-08-03

## 一、用户只需要理解的一条路径

每个产品的首次分发固定为五步：

1. 确认产品事实。
2. 添加可复用素材。
3. 选择一个具体目标站。
4. 生成目标站专属材料包。
5. 人工提交并记录审核或上线结果。

平台负责目标站建议、材料准备、UTM、状态追踪和复查提醒。用户负责确认事实、处理第三方账号或验证码、最终提交和记录真实结果。

如果存在可安全复用的 AI Best Tool 产品，Step 1 会显示 `AI Best Tool connection`：

- 普通用户只有在 `submitted_by` 或提交邮箱与当前账号匹配时才能导入。
- 平台管理员可以连接其他账号提交的产品，但项目官网与条目官网必须精确同域。
- 已有项目官网时，只有相同官网域名的产品可以导入。
- 导入名称、官网、描述、分类、价格上下文、Logo 和截图，但不会导入评分、排名、评论或编辑评价。
- 导入内容只是待确认快照；必须由 owner 复核并勾选事实确认。
- 产品类型会调整素材要求和目标站排序，但不会替用户自动提交。

## 二、Moxion 首次验收数据

### Step 1：产品事实

- 产品名：`Moxion`
- 官网：`https://moxion.ai`
- 建议目标：首次验收选择 `Directory coverage`
- 建议周容量：`3`
- 建议预算：`Free first`
- 建议描述：`Moxion helps creators and marketers create, optimize, compress, resize, and convert GIFs from text, images, or video for social media, ecommerce, ads, Discord, and product demos.`
- 事实来源：`https://moxion.ai/`

保存前必须由产品 owner 核对描述，并勾选 `Facts reviewed and confirmed`。不得使用首页异常显示的统计数字作为证明。

### Step 2：素材

最低验收要求：

- 一个可公开访问的官方 Logo 或 Icon URL。
- 一个真实产品界面或生成结果截图，推荐但不是进入下一步的硬阻塞。
- URL 必须可在未登录状态通过 HTTPS 打开。
- 只有 owner 确认来自官方产品时才勾选 `Verified first-party asset`。

### Step 3：目标站

首次只选择一个目标站，不批量接受。选择前检查：

- 受众是否适合 GIF、设计、营销或创作者工具。
- 是否收费。
- 是否需要账号、验证码或互链。
- 是否存在可验证的提交入口。
- 预计人工时间是否可以接受。

点击 `Choose this target` 后必须生成一条绑定具体目标站的任务，并显示 `Continue task`。

### Step 4：材料包

进入任务页，点击 `Generate target package`。验收：

- 可看到具体目标站名称和提交入口。
- 标题、描述、产品 URL、Disclosure 和 Proof points 可逐项复制。
- 目标站字段长度限制可见。
- 缺少的素材或字段会明确阻止 `Ready for human submission`。
- 重新生成不会创建重复任务或跨产品读取素材。

### Step 5：提交与记录

- 在目标站人工提交，不自动发布。
- 提交后标记 `Submitted`，系统生成 3 天和 7 天复查。
- 审核中标记 `Waiting review`。
- 上线后保存真实 URL 和链接状态，系统生成 7、30、90 天复查。
- 被拒绝时记录真实原因，不伪造 live URL。

### 当前阶段式页面规则

- 未确认产品事实：只突出 Step 1 表单；不展示目标站、空任务、UTM、归因和渠道手册。
- 产品事实已确认但素材不足：展开 Step 2 素材中心。
- 资料与素材就绪：把已完成模块压缩为摘要，并直接展示 Step 3 目标站推荐。
- 已接受目标站：展示该目标对应的任务、材料包、UTM 和执行控件。
- 已提交：再展示审核、上线、归因和复查数据。
- 每个阶段首屏只能有一个主要 CTA；自定义任务和高级统计不得压过首次分发路径。

## 四、DC-019 完成口径

对三个真实产品各完成至少三个目标站：

- 项目、素材、任务和材料包归属正确。
- 目标站选择理由和人工障碍清楚。
- 材料包没有虚构事实。
- 提交、审核、上线或拒绝状态可追踪。
- 3/7/30/90 天提醒按状态生成。
- 全程不依赖表格、Notion 或外部日历管理。

## 五、分发与外链质量门槛

分发的目标不是增加“已提交”数量，而是获得与产品受众相关、可验证、可持续复查的真实提及或链接。每个目标站必须满足以下准入要求：

- 目标站受众与产品场景匹配，不能只因为“能留链接”就进入今日队列。
- 提交入口、收费、账号、验证码、互链和内容限制已记录；未知项明确标记未知。
- 针对同一目标站使用独立材料包，不复制粘贴完全相同的宣传文案。
- 产品事实、价格、截图和 proof point 只能来自 owner 已确认资料或可复核的官方来源。
- 所有站外落地链接使用项目级 UTM，并绑定具体渠道、目标站和 campaign。
- `Submitted` 只表示已提交；只有保存公开可访问的真实 URL 后才能标记 `Live`。
- `Live` 不自动等于有效 backlink；必须记录链接是否存在、是否可抓取以及 `follow` / `nofollow` / `ugc` / `sponsored` 属性。
- 上线后执行 7、30、90 天复查；链接被删除、页面失效或内容被改写时同步更新状态。

### 数量与节奏

- 冷启动阶段每个产品每周优先完成 3-5 个高相关目标，不以每天批量提交为 KPI。
- 同一周同时覆盖目录、社区或内容合作等不同渠道，避免只依赖低门槛目录。
- 任何需要垃圾互链、虚假评价、批量账号或与受众无关的目标站都应标记 `Blocked` 或 `Skipped`。

### 结果计数规则

| 状态 | 可以计入提交 | 可以计入 live mention | 可以计入 backlink |
| --- | --- | --- | --- |
| Planned / In progress | 否 | 否 | 否 |
| Submitted / Waiting review | 是 | 否 | 否 |
| Live，但未保存公开 URL | 是 | 否 | 否 |
| Live，公开 URL 可访问但无产品链接 | 是 | 是 | 否 |
| Live，公开 URL 可访问且产品链接已核验 | 是 | 是 | 是 |

平台周报必须分别展示提交数、live mention 数和已核验 backlink 数，禁止把三者合并成一个“外链完成数”。
