# 一周高质量收录与 Decision Card 实施计划

周期：从下一次工作日开始连续 7 天
状态：执行中
上位规范：[高质量收录与 "Best" 定位执行规范](./BEST_DIRECTORY_POSITIONING_AND_INTAKE_CN.md)

## 已完成的复核

当前详情页已具备部分基础：官方事实快照、编辑复核、适合/不适合、风险限制、相似工具和评论入口。

但仍有四个关键缺口：

1. 同一套决策信息散落在“快速判断”“Decision Guide”“决策摘要”等多个区块，存在重复，用户无法一眼知道先看什么。
2. 完整官方证据目前只覆盖优先工具子集，普通新工具没有统一的资料完整度与待补项显示。
3. 资料字段、审核结论、来源、下次复查日期和公开资格尚未成为一个可追踪的发布工作流。
4. 分类页、Guide 与详情页已有链接，但还没有统一消费同一份 Decision Card 的任务入口与比较结论。

结论：不应新增一个独立的 Decision Card 页面；应把它做成每个工具页唯一、可复用、可审计的顶部决策模块，并由其他页面链接到它。

## 每日收录规则

- 每天至少处理 1 个、最多处理 2 个工具的完整收录流程。
- “处理”包括发现、核验、编辑和准入；只有通过所有公开资格的条目才会公开发布。
- 若当天候选不合格，必须记录拒绝/待补原因，转为 draft 或 `noindex`，不能以数量目标绕过准入。
- 为稳定实现每天至少 1 个公开条目，候选池始终保留未来 3 天的已核验备选；不足时优先补候选池，不临时使用低质量产品。

## 工具页最终显示顺序

1. 产品身份与一句话任务定位。
2. **Decision Card**：Best for、Watch outs、Compare next、编辑的首要核验建议。
3. 官方事实与证据：定价/限制、来源、最后核查、下次复查。
4. 产品能力与预览素材。
5. 编辑复核、owner 更新、评论与纠错。
6. 相似工具和下一步行动。

重复的“快速判断”和“决策摘要”将收敛为一个主模块；深层证据仍保留在后方，供准备决策的用户查证。

## 风险控制

- 不扩大 URL：优先补现有 canonical 页面；新工具只在意图独立时才建公开 URL。
- 不编造事实：AI 只整理公开材料和生成待审草稿，官方来源与关键限制必须可点击复核。
- 不把待审产品公开：付费、owner 认领或提交并不等于自动获得 indexable 页面。
- 每次代码改动必须先完成本地 `pnpm run build`，再推送 `main`。

## 本周成功定义

- 公开详情页有一个清晰且不重复的 Decision Card。
- 后台和前台能共同追踪发布资格、证据、缺失项与复查日期。
- 处理至少 7 个、最多 14 个候选流程；公开数量仅计算通过准入的条目。
- 已有曝光的非首页页得到增强，而不是被新页面淹没。
