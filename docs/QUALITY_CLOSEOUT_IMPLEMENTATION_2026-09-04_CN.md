## 四、实施细节与验收契约

- 不新增数据库表或迁移。事实维护复用tools.features中的editorial/maintenanceReview/marketValidation以及next_review_date；不同证据范围分别记录，禁止一次更新刷新所有验证时间。
- 每条变更记录固定ID/slug、旧值、来源URL、核对范围、执行时间、复查日期、测试命令和结果。未知字段保留未知。
- 写入前先只读查重及影响面审计，再事务预演；断言除允许字段外所有业务字段不变，正式写入后独立连接回读，再检查双语正文与fallback。
- canonical、301、noindex、sitemap变更单列审批和验收。内容核验不等待GSC；旧URL迁移不可因缺少GSC而推断零流量。四页数据最小集见历史对象文档。
- 回滚用逆向补丁或保留旧值的补偿事务，不覆写用户后续修改，不自动翻转已上线索引状态。任一测试失败，不标完成、不推送触发部署。
- 完成状态流程：待执行→进行中→本地验收通过→生产验收通过（需要发布的任务）；数据依赖单列；持续监测不改成永久完成。

## 五、自动化验收

1. `pnpm run test:plan-consistency`：从四周一级表自动统计；验证当前文档不得恢复旧导航待修语句、关键任务映射及本方案链接。含错误状态、重复ID、缩小统计分母的反例；只读，不自动将任务升级为完成。
2. `pnpm run test:reviewed-tool-relationships`：结构而非缩进校验，原生a保留本地化href；错误Link及缺href必须失败。
3. `pnpm run test:guide-link-boundaries`、`pnpm run test:seo-architecture`、`pnpm run test:seo-breadcrumbs`、`pnpm run test:localized-navigation`：保护既有架构。
4. `pnpm exec tsx scripts/maintain-tool-review-schedules.ts --inventory`只读；`--test`验证日期推导。不可用默认写入/commit模式来证明19项已完成。
5. `pnpm run build`完整退出0；涉及页面部署才在main推送后核对Vercel及生产smoke。首轮仅文档/验收脚本/CI，不需数据库执行或页面部署。
